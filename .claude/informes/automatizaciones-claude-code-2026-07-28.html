Perfil del codebase

  • Tipo: Sitio estático Jekyll (Ruby), sin Node/npm
  • Stack: Bootstrap 3.4.1 (Sass) + plantilla Clean Blog (LESS), jQuery 1.12.4, sin framework JS moderno
  • Contenido: 166 posts en español sobre UX/accesibilidad, hosting en GitHub Pages + Cloudflare
  • Automatización ya existente: 5 skills propias (publish-post-blog-aunitz, republish-theconversation-aunitz, enlazado-interno-ultimo-post-aunitz, web-performance-optimization, claude-automation-recommender), plugin claude-seo activado, script Ruby check_links.rb para enlaces rotos

🔌 MCP Servers

GitHub MCP

Por quéEl sitio se despliega vía GitHub Pages y depende de un workflow de Actions (purge-cloudflare-cache.yml) que se dispara en cada deploy. Un MCP de GitHub permitiría consultar el estado de esos runs, revisar deploys fallidos o gestionar issues/PRs sin salir de la conversación.

Instalar

claude mcp add github

context7

Por quéEl stack usa versiones "congeladas" y antiguas (Bootstrap 3.4.1, jQuery 1.12.4). Al tocar CSS/JS de esas librerías, context7 da la documentación exacta de esa versión en vez de arriesgarse a mezclar sintaxis de versiones más modernas.

Instalar

claude mcp add context7

check-enlaces-rotos Solo usuario

Por quéYa existe check_links.rb en la raíz del repo pero no está empaquetado como skill invocable. Con 166 posts y una skill que añade enlazado interno activamente (enlazado-interno-ultimo-post-aunitz), tener un /check-enlaces-rotos que compile el sitio y ejecute el script tras publicar o enlazar sería el complemento natural.

Crear.claude/skills/check-enlaces-rotos/SKILL.md

---
name: check-enlaces-rotos
description: Compila el sitio con Jekyll y ejecuta check_links.rb
  para detectar enlaces internos/externos rotos
disable-model-invocation: true
---

sync-claude-agents-md Ambos

Por quéEl propio CLAUDE.md advierte que AGENTS.md es un fichero gemelo que hay que mantener sincronizado a mano — es un punto de fallo silencioso si algún día se edita uno sin el otro.

Crear.claude/skills/sync-claude-agents-md/SKILL.md

⚡ Hooks

Aviso al editar CLAUDE.md sin tocar AGENTS.md

Por quéEs la regla de mantenimiento explícita del propio proyecto. Un hook PostToolUse que detecte una edición a CLAUDE.md y recuerde revisar AGENTS.md (o viceversa) evita que se desincronicen con el tiempo.

Dónde.claude/settings.json

Bloqueo de edición directa de CSS/JS compilados

Por quéLas convenciones del proyecto prohíben editar css/bootstrap.min.css, css/clean-blog.min.css o js/clean-blog.min.js directamente (se compilan desde bootstrap-sass/ y less/). Un hook PreToolUse que bloquee Edit/Write sobre esos ficheros evita tocar el artefacto compilado en vez del origen.

Dónde.claude/settings.json

🤖 Subagentes

seo-post-reviewer

Por quéEl blog es también herramienta de posicionamiento SEO/autoridad para Aunitz y Adimedia. Un subagente que revise un post recién creado contra un checklist (longitud de description, alt en imágenes, jerarquía de encabezados, densidad de enlazado interno, corrección del frontmatter de schema.org) daría una segunda pasada de calidad antes de publicar.

Dónde.claude/agents/seo-post-reviewer.md

accessibility-reviewer

Por quéYa existe una skill (accesibilidad-medios-posts-aunitz, en .agents/skills/) centrada en alt/title de medios. Un subagente más amplio de accesibilidad (contraste en estilos inline, semántica de encabezados, calidad del texto de enlace) encaja con el enfoque UX/accesibilidad del propio blog.

Dónde.claude/agents/accessibility-reviewer.md
